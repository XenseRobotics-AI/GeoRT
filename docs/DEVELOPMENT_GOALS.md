# 开发任务：基于现有 GeoRT 项目改进灵巧手重定向

你正在当前灵巧手重定向代码仓库中工作。请先阅读项目中的 AGENTS.md、README、训练和推理入口，再依据实际代码完成本任务。

这是一个需要落地代码、测试和实验配置的开发任务，不是只输出研究建议或设计文档。请先进行必要的代码审计，然后实施最小但完整的第一版改进。

不要把本文对项目的描述当作已经核实的代码事实。输入结构、网络结构、损失实现、机器人模型和数据格式，都必须以当前仓库为准。

---

## 一、背景与目标

当前讨论面向 Manus Glove → 灵巧手的重定向，目标机器人重点考虑 Wuji，但应保留项目已有机器人和数据集的兼容性。

我们希望改进的不是单纯的指尖位置误差，而是以下问题：

1. 指尖位置相同或接近时，人手仍可能具有不同的末节方向、指腹朝向和弯曲分配。
2. 逐指独立映射可能不足以表达依赖其他手指状态的协同动作。
3. 机器人较大的关节活动范围提供了更多构型选择，但无条件扩大覆盖可能损害常用操作的精细控制。
4. 几何误差下降不一定意味着遥操作更直观、更稳定或更好用。
5. 仅增加 loss，无法弥补输入中缺失的信息。

本次采用如下工作定义：

“好的灵巧手重定向，是在人与机器人结构不一致的条件下，保留任务相关的动作关系、接触方式和可理解的手型，使操作者能够连续、精细、低负担地调用机器人的有效操作能力。必要时允许偏离人体构型，但这种偏离应有明确的功能收益，并保持可预测。”

具体优先关系：

- 安全与可执行性是底线。
- 优先保留任务相关的多指关系和方向信息。
- 在满足主要操作要求的构型中，优先选择自然、连续、符合操作者预期的解。
- 扩展覆盖不能以破坏常用操作的精细控制为代价。

注意：直接决定接触方式的手型特征属于任务目标，不能全部降级为次要的“外观正则项”。

## 二、首轮范围

本轮必须完成：

1. 审计现有输入、数据流、模型、FK、loss 和推理接口。
2. 保留可复现的原始 baseline。
3. 在真实数据能力允许的前提下，增加可选的骨段/姿态输入。
4. 增加最小的全手上下文协调能力。
5. 增加可配置的多指关系、方向和手型损失。
6. 建立局部增益、死区、覆盖与时间质量的诊断能力。
7. 增加测试、消融配置和使用说明。
8. 完成可执行的最小训练/推理验证。

本轮不要求：

- 重写整个训练框架。
- 引入大型 Transformer、强化学习或复杂生成模型。
- 同时解决完整手内操作和自主抓取。
- 在没有物体信息时实现真实接触保持或抓取稳定性判断。
- 默认运行长时间训练。
- 自动连接并驱动真实机器人。

局部增益优化、有效覆盖重设计和复杂时序模型，本轮以诊断和可选实验接口为主，不要与输入、模型结构、核心 loss 同时进行大规模重构。

## 四、输入与兼容性要求

### 4.1 保留原有模式

必须保留原始指尖输入、旧数据集、旧 checkpoint 和旧推理入口的可用性。

建议形成明确的输入模式，例如：

- tip_only：使用原有可用输入。
- skeleton：增加真实可用的骨段位置或方向。
- pose：在具有可靠姿态数据和坐标标定时增加姿态特征。

具体命名与当前项目风格保持一致，不必机械套用上述名称。

### 4.2 不得虚构可观测信息

必须遵守：

- 只有指尖位置时，不能声称能够恢复真实的中间指节姿态。
- 只有骨段轴向时，不能声称已经获得完整指腹朝向。
- 不得把缺失方向填成零向量后当成有效监督。
- 不得把人手关节角直接当成机器人关节真值。
- 不要求不存在的人机成对关节标签。

对缺失、低置信度、退化骨段和非有限数据，使用显式有效性 mask，并记录有效样本比例。

用户显式启用某项能力，但必要数据缺失时，应给出明确错误。若提供自动降级模式，必须在日志中明确说明实际启用和禁用的功能，不能静默降级。

### 4.3 特征与标定

统一处理：

- 手指及关键点索引。
- 左右手。
- 长度和角度单位。
- 坐标变换。
- 四元数顺序及旋转约定。
- 人体骨段与机器人骨段的对应关系。
- 机器人指尖、末节和指腹局部轴定义。

对于无法从模型或已有标定可靠确定的轴，不得随意猜测。

新增特征定义、顺序、归一化参数和标定配置应进入 checkpoint 元数据，避免训练与推理不一致。

不要为本任务修改无关的数据采集 schema。必要的扩展优先通过兼容的适配器和可选字段实现。

## 五、模型改进：保留基础映射，增加最小的全手协调

优先评估以下方案：

“原有逐指映射 + 轻量全手上下文协调模块”。

可根据仓库结构选择：

- 向逐指分支提供共享全手特征；
- 或在原始输出上增加受控的全手残差修正。

不强制采用某个固定网络，但必须满足：

1. baseline 路径仍然独立可用。
2. 输入模式与是否启用全手协调可以分别配置。
3. 全手协调模块能读取真实存在的其他手指信息。
4. 新模块初始化不应造成输出的大幅突变。
5. 不得采用导致整个新增模块永久无法学习的初始化或门控方式。
6. 输出仍经过与现有系统一致、可解释的关节边界处理。
7. 不得通过放宽关节限位来改善训练 loss。

若使用残差，明确其作用空间、尺度和边界处理，避免残差绕过原有安全约束。

不要为了“协同”强制所有手指始终一起运动。目标是允许任务相关的协调，同时保留必要的单指微调能力。

新增模型应检查 checkpoint 的结构、特征和机器人配置兼容性。不要用宽泛的 strict=False 静默忽略不匹配参数。

## 六、损失函数设计

保留原有 loss 作为 baseline。新增 loss 均需：

- 单独配置开关和权重。
- 具有清晰的物理或操作含义。
- 进行尺度或容差归一化。
- 支持有效性 mask。
- 记录原始值、归一化值、加权值和有效样本数。
- 有数值稳定性和梯度测试。

不要只输出一个无法诊断的 total_loss。

### 6.1 多指关系损失

优先关注：

- 拇指与其他手指的相对关系。
- 两指开口宽度。
- 两指共同移动与相对闭合的区别。
- 必要的多指组合关系。

可使用相对向量、距离、方向或经过定义的操作特征。

要求：

- 考虑人机尺寸与可达范围差异。
- 不要简单把所有人手距离原样复制给机器人。
- 不要将所有指尖坐标重合当作正确捏合。
- 区分模型 site、指腹表面和真实接触点。
- 不引入没有依据的“强制吸附闭合”。
- 不用人手未提供的物体或接触信息构造虚假监督。

若现有 pinch loss 已覆盖某部分需求，应扩展或复用，不要重复计罚却没有说明。

### 6.2 方向损失

依据真实可用信息分层实现：

- 末节轴向。
- 其他骨段方向。
- 经可靠标定的指腹法向。
- 仅在确有完整姿态时考虑完整旋转约束。

要求：

- 人机方向先转换到一致且有意义的坐标系。
- 方向向量归一化，退化向量使用 mask。
- 不要默认正反方向等价，避免用绝对点积掩盖方向翻转。
- 机器人方向应来自明确的 FK 和局部坐标定义。
- 不要为了匹配人体朝向要求机器人达到机械上不合理的构型。
- 如果人体信息只能约束一个方向，不要虚构其余姿态自由度。

### 6.3 手型先验损失

目标是在满足主要操作要求的构型中，选择更合理、自然、可预测的手型。

优先考虑：

- 骨段相对方向。
- 手指弯曲方向。
- 弯曲在不同指节之间的分配。
- 可解释的伸展、勾曲和包络特征。

不把“机器人关节角等于人手关节角”作为默认目标。

人机结构不一致时，应使用明确的特征对应和容差，而不是强制一一对应。

区分：
- 直接决定操作方式的手型约束；
- 仅用于选择剩余构型的自然性正则。

不要让自然性正则压过必要的捏合或接触方向要求。

### 6.4 局部可控性

首轮必须先建立诊断：

- 方向保持误差。
- 不同区域的局部增益分布。
- 死区比例。
- 接近关节边界时的饱和行为。
- 同一动作在不同姿态下的响应变化。
- 单指动作引起的其他手指响应。

注意：

- 机器人没有明显移动时，方向误差本身没有意义，需要同时统计低响应和死区，不能只删除这些样本。
- 骨骼输入的扰动应尽量来自真实邻近姿态或一致的运动学扰动，不能通过任意移动单个骨骼点制造大量不合理姿态。
- 分别观察整体移动、开口调节和方向变化，不要默认它们需要同一个增益。

若实现可选的局部响应 loss，先采用明确配置的目标或边界，避免目标增益和模型同时无约束学习，导致平凡解。

本轮不要求“全空间处处等增益”。

### 6.5 有效覆盖

保留原有 coverage 行为作为 baseline。

新增诊断应区分：

- 单指可达范围。
- 多指组合可达性。
- 常用操作区。
- 极端关节区。
- 是否能够保持和微调，而不仅是偶然到达。

只有存在独立、明确的可行参考集合时，才报告有意义的覆盖率，并说明采样与容差。

不要直接将更大的关节范围或更高的逐指覆盖认定为更好的重定向。

本轮不通过大幅增加 coverage 权重来强迫全范围展开。

### 6.6 时序质量

只有真实连续序列和时间信息可用时，才实现时序训练项。

禁止：

- 把随机 batch 中相邻两行当作连续时间帧。
- 用不动的输出换取低平滑损失。
- 忽略滤波造成的响应延迟。

评估时同时记录跟随误差、运动幅度和抖动。速度、加速度等计算应使用正确时间间隔。

若没有连续数据，可以完成相关接口和合成测试，但必须说明真实时序性能尚未验证。

### 6.7 安全与梯度

- 保留关节限位、自碰撞相关逻辑和运行时安全检查。
- 正常指腹接触与非法穿透不能混为一谈。
- 训练软惩罚不等于运行时安全保证。
- 若训练使用近似 FK，尽可能使用独立精确 FK 进行验证。
- 检查新增方向和手型计算是否真正可微。
- 不得因调用 NumPy、detach 或不可微 FK 而让新增 loss 看似正常、实际无法更新模型。
- 若依赖不支持可微计算，应采用项目已有的可微实现、可用解析雅可比或明确报告该限制。

## 七、实验与消融

默认行为保持 baseline；新增功能通过明确的实验配置启用。

提供可逐步增加能力的消融配置，例如：

B0：原始模型、原始输入、原始 loss。
B1：B0 + 全手上下文，保持输入信息和 loss 不变。
B2：B1 + 真实可用的骨段/姿态输入，保持 loss 不变。
B3：B2 + 方向损失。
B4：B3 + 手型损失。
B5：B4 + 多指关系改进。

具体顺序可根据实际代码调整，但必须能区分：
- 输入信息带来的收益；
- 网络结构带来的收益；
- loss 带来的收益。

数据不足的配置应明确标为暂不可运行，不得用零填充伪装成完整实验。

实验要求：

- 固定数据划分、随机种子和训练预算。
- 优先按完整序列、采集会话或操作者划分训练/验证集。
- 避免相邻帧随机拆分造成泄漏。
- 新权重初值应标明是待调参的起点，而不是最优设置。
- 提供运行命令，但本轮不默认执行全部长训练。
- smoke test 通过不能表述为重定向质量已经提高。

至少支持输出：

- 原有指标。
- 指尖方向误差。
- 多指关系/开口误差。
- 手型特征误差。
- 局部增益和死区。
- 约束违反及安全修正情况。
- 推理耗时。

方向、手型等指标只在有效数据上统计，并报告覆盖的样本比例。

模型计算耗时不能写成整套系统端到端延迟。

## 八、测试与验收

根据当前项目测试框架补充以下测试。

### 8.1 兼容性

- 原始输入可运行。
- 原始 checkpoint 可加载到原始路径。
- 所有新增功能关闭后，与原始行为一致。
- 原始命令和数据格式不被破坏。

### 8.2 几何与数据

- 关键点、手指和关节索引正确。
- 坐标转换和单位一致。
- 左右手与四元数约定正确。
- 刚体变换前后，定义为相对量的特征保持一致。
- 指腹法向和末节轴向不被混淆。
- 退化骨段、缺失字段、NaN/Inf 得到明确处理。

### 8.3 loss 与梯度

- 理想对应时，相应 loss 接近预期最小值。
- 有意义的扰动会增加对应 loss。
- 方向反转不会被误判为相同方向。
- mask 正确排除无效样本。
- 全部样本无效时不出现 NaN，并能被日志识别。
- 梯度能够回传到重定向网络参数，而不只是 FK 输出。
- 关节边界附近不出现异常数值行为。

### 8.4 信息与协调能力

构造以下诊断案例：

1. 指尖位置接近、末节方向不同。
   - tip_only 模式不得被声称能区分缺失信息。
   - 增强模式的输入表示应能够区分这类动作。
   - 未经真实训练，不要据此声称已学会正确输出。

2. 某指自身输入相同、其他手指状态不同。
   - 全手上下文路径应具有表达不同输出的能力。
   - 不强制未经训练的模型必须产生正确的协调动作。

3. 连续的小幅输入变化。
   - 检查有限性、输出变化和局部增益。
   - 不允许新增分支引入明显的无依据硬切换。

### 8.5 最小运行验证

在现有环境允许的条件下完成：

- 数据读取。
- 特征构建。
- 前向计算。
- 各 loss 计算。
- 反向传播。
- 少量优化步骤。
- checkpoint 保存与重新加载。
- 离线或仿真推理。

使用小 batch 和有限步数。没有 GPU 时，优先验证能够在 CPU 上完成的部分。

若真实数据不可用，可使用清楚标注的合成数据验证形状、数值和梯度，但不能用其证明实际操作性能改善。

## 九、工程边界

- 遵循当前项目代码风格，优先最小必要改动。
- 不进行与任务无关的大范围重构。
- 不覆盖原始数据、训练结果和 checkpoint。
- 不修改系统驱动、机器人固件或硬件关节限位。
- 不为方便而大规模升级依赖。
- 不自动连接或移动真实机器人。
- 不自动执行 git push、破坏性 reset/clean 或其他不可逆操作。

- 新增依赖确有必要时，说明原因与影响。
